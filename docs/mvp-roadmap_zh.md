状态：2026-10-11 更新。M1 已通过离线检查、独立审查，以及所有者要求的全新子代理走查，完成验收；M2 实现、独立审查及自动离线／Compose 验收已完成；所有者已于 2026-10-11 确认人工走查通过。M3–M4 仍待实施。[M1 完成记录](milestone/m1_zh.md#4-检查与完成记录)包含验证证据及限制。

## 1. 目标与首版边界

为内部操作人员交付以下流程：

**准备树莓派 → 通过本地页面配置现场和 P1 → 将登记信息复制到中心端 → 采集、本地保存并上传 → 查找现场数据并导出 CSV。**

Logger 以树莓派 4（1 GB）为目标，同时必须支持树莓派 3B+。Centralized Server 以容器方式运行在所有者家中具备公网访问条件的服务器上。试点从一台 Logger 开始，一个监测会话只使用一个 P1 来源；预计后续增长到几台设备。MVP 唯一电表 profile 为荷兰 DSMR 5（`dsmr5_nl`），依据 DSMR 5.0.2；其他电表 profile 后续再加。

规划目标约为一到两周开发时间，前提是硬件、P1 线、测试电表和宿主机环境已经具备。各 Milestone 估算合计 6–10 个工作日，属于估算而非交付保证；电表适配和硬件故障可能延长周期。软件可用与完成数周现场监测是两个不同的结果。

| MVP 包含 | 后续迭代 |
| --- | --- |
| 本地配置、P1 试读、采集控制和状态 | Modbus TCP、串口 RS485/RTU 及其他来源 |
| Site UUID、设备凭据、中心端人工登记 | 自动 provisioning、远程配置及升级 |
| 10 秒快照、SQLite 备份、可靠批量上传 | 图表、衍生用电统计、AI 报告及 PDF 导出 |
| 中心端鉴权、存储、现场／设备状态、筛选查询及 CSV | React 界面扩展、客户账号、电池／光伏容量建议 |

SSH、网口地址、DHCP、Wi-Fi、公网连接和 WireGuard 均由所有者在项目外准备和管理。应用不配置宿主机网络、不运行 DHCP 服务，也不管理 VPN 密钥。现场操作人员用电脑连接树莓派，先建立宿主机层面的互通，再通过可达地址打开本地页面。

## 2. 身份、配置与数据归属

### Site UUID 与监测会话

- 新建现场时，Logger 生成随机 UUID v4 作为 `site_id`，并在开始采集前将其与地址、简介一起保存。离线也能完成。中心端沿用这个 UUID，不另行生成替代值。
- Site UUID 标识现场，而不是设备或凭据。修改地址、简介、重启 Logger 或更换 Token 都不改变该 UUID；它不从地址或 Token 派生。
- 本地页面提供**新建现场**和**使用已有 Site UUID**。再次监测同一现场时复用 UUID，并建立新的监测会话；不通过地址匹配推断身份。
- 分别保留 Logger 设备、现场、监测会话、测量点和来源的身份。MVP 每个会话仅使用一个 P1 来源，不需要多电表配置界面。
- 每条快照保留现场、设备、会话、测量点、来源及稳定记录 ID。Logger 转移到新现场时开启新会话，已存储和待上传记录保持原归属。
- 停止／启动和进程重启延续未结束的监测会话。明确结束、换现场或确认换表后新建会话／source；同一现场保留并网测量点。

### 凭据与人工登记

- Logger 首次配置时生成独立随机 Bearer Token，持久保存到受保护的本地数据目录，允许已认证的操作人员复制。重启及普通配置修改不重新生成。
- 展示可复制的登记摘要，包括 Site UUID、地址、简介、设备标识和 Token。Token 不进入读数、CSV 或日志。
- 管理员人工创建或选择现场，登记设备和 Token，并授予设备访问该现场的权限。中心端仅保存 Token 哈希，支持停用设备凭据。
- UUID 已存在时，复用中心端现场记录，不静默覆盖其信息。中心端地址和简介的修改由管理员显式操作。
- 有效 Token 用于认证设备，不意味着设备可以写入任意 Site UUID。未知或未授权现场的请求被拒收，不确认其读数；Logger 保持这些读数待上传。
- 为设备登记新现场时，保留其旧现场授权以便补传，除非管理员显式移除该授权或停用设备凭据。
- 本地配置凭据、中心端管理员凭据和上传 Token 分别授权。首版操作账号通过部署配置提供，账号管理功能后续再做。

## 3. 运行与采集行为

### Data Logger

- 使用 Raspberry Pi OS Lite 64 位、ARM64 容器、Python/FastAPI、`pyserial`，以及持久化卷内的 SQLite。一个应用进程负责采集、上传和本地 API。树莓派上不运行 Node.js、独立数据库服务或 AI 模型。
- 提供简单 HTML 页面和少量 JavaScript，配置现场、中心端 URL、P1 串口路径与参数及已安装电表 profile；提供试读预览、启动／停止和状态。解析规则由应用维护，不在现场编辑。
- 持续读取并校验完整 P1 报文。每个 10 秒窗口结束时最多保存一条快照：该窗口内收到的最新一条新有效报文，包括全部脱敏解析字段、原始设备时间、接收时间及质量信息。
- 窗口内没有新有效报文时保留缺测，不给旧读数换一个新时间戳。DSMR 5 profile 拒收 CRC 不匹配及无法校验的帧。保留安全的标准字段，包括附属计量；设备标识、自由文本和未知字段值脱敏，未知 code 及脱敏标记保留。
- 时间统一保存为 UTC，同时保留原始电表时间。进口／回送累计电量保持精度，缺失字段保留缺测，缺相不填零。原始串口字节不作为长期记录保存。
- 发送前先提交快照及待上传状态。本地保留整次监测，包括已上传记录。仅允许手动清理已完成会话中的已上传记录，待上传记录必须保留。
- 展示最近有效读数时间、采集错误、最近上传成功时间、鉴权／上传错误、积压及存储压力。容量不足时告警并停止新增记录，不删除旧数据，也不静默显示为采集正常。

10 秒快照每天最多 8,640 条，四周最多 241,920 条。这不意味着 SD 卡寿命增加十倍。避免逐条报文日志和逐条上传确认更新，保留数据库持久化可靠性，并在目标设备上测量实际磁盘写入。后续用电统计应使用累计电量；瞬时快照不能确定所有短时功率峰值。

### Centralized Server 与回传契约

- 使用 Docker Compose、Python/FastAPI、PostgreSQL，公网 HTTPS 入口使用 Caddy。首版由后端提供简单 HTML 表单、列表和数据表；React 留作后续界面选项。
- 提供管理员登录、现场及设备登记、授权管理、状态、读数筛选查询和 CSV。支持通过 UUID 或地址查找现场，再按会话、设备和时间筛选读数。
- 保存所有接纳的快照，常用电力指标使用可查询字段，其余脱敏字段使用 JSONB。接纳的快照至少保留一年，本地清理不删除中心端历史。
- 上传使用配置的中心端 URL。公网使用 HTTPS，也支持所有者管理的 WireGuard 隧道内 HTTP。采集和 onboarding 不依赖 WireGuard，也不要求中心端立即可达。
- 正常每 10 秒尝试上传，使用有大小上限的批次，最多一个请求在途，并设置超时和重试退避。网络恢复后连续补传积压，成功的积压批次之间不强制等待 10 秒，也不阻塞采集。
- 对整个批次完成鉴权和授权检查，在原子事务提交后确认成功。按设备及稳定记录 ID 去重；无效批次不作部分确认。
- Logger 收到持久化确认后才标记已上传。超时或响应丢失时保持待上传，重试使用原记录 ID。上传状态按已确认批次分组更新。
- 分别记录设备最近一次已认证联系时间和最新读数时间。补传期间联系成功不代表正在产生新测量数据。

[M1 公共契约](milestone/m1_zh.md)在后续实现前固定接收 endpoint、payload schema、批次限制、迁移边界和串口生命周期。M1 可执行类型、诊断 probe 和离线检查已经实现并通过独立审查；C5 存储仍是供 M2／M3 实施的规范。上述行为和身份边界已经确定。

## 4. Milestone 与验收

按 **M1 → M2 → M3 → M4** 推进，每个 Milestone 验收通过后再进入依赖它的工作。开始该阶段前，将实现拆成具有边界、验收标准和检查项的小任务卡；本文本身不启动委派编排。每个 milestone 在 `docs/milestone/` 下维护一份英文文档及中文镜像；[M1 文档](milestone/m1_zh.md)内包含设计、契约及八个原子任务章节。[M2 设计](milestone/m2_zh.md)规定独立 Logger 契约及十个顺序原子任务；实现及自动离线验收已完成；所有者已于 2026-10-11 确认人工走查通过。

| Milestone | 交付内容 | 验收标准 | 估算 |
| --- | --- | --- | --- |
| **[M1 — 协议与契约](milestone/m1_zh.md)** | 独立项目骨架、P1 解析提取、电力字段映射及脱敏样本、身份／存储／上传契约 | 解析及映射检查通过；DSMR 5 profile 串口默认参数和字段明确，实物电表／线材兼容在 M4 验证；契约区分现场、设备、会话、来源和记录身份 | 1–2 天 |
| **[M2 — 独立可用的 Logger](milestone/m2_zh.md)** | 本地配置和试读、Site UUID 与 Token、10 秒快照、SQLite、采集生命周期、状态；Logger Dockerfile／Compose 和本地浏览器走查 | 本地 Compose 构建／启动及浏览器走查通过；离线可配置和采集；重启保留身份、配置、读数及待上传状态；断线可恢复；换现场保留旧记录归属 | 2–3 天 |
| **M3 — 人工纳管的中心端** | Server Dockerfile／Compose、PostgreSQL 与 Caddy 配置、本地浏览器走查、登录、现场／设备登记、授权批量接收、状态、筛选查询及 CSV | 本地 Compose 构建／启动及浏览器走查通过；未知凭据／现场被拒收；登记后可接收；重放不重复入库；可按 Site UUID 查找数据；CSV 与查询一致 | 2–3 天 |
| **M4 — 完整试点版本** | Logger 上传及补传、集成开发 Compose、验证后的 Logger／Server 部署配置、端到端状态、硬件／资源验证及操作说明 | 容器化配置到 CSV 走查通过；断网、进程重启及响应丢失后可恢复；新旧现场不混淆；Pi 4 1 GB 与 3B+ 验证通过 | 1–2 天 |

### 容器交付与浏览器验收

从 M2 开始，每个新增或修改可运行模块的 Milestone，必须在同一阶段交付对应的容器构建文件和 Docker Compose 配置；只有源码不算模块交付完成。后续图表／报告 worker、Modbus 支持及运维模块同样遵守：扩展相应镜像／Compose 服务，或按需增加独立服务，同时交付配置与验证。这些是后续必需交付物，M1 中尚不存在这些文件。

| 阶段 | 必需容器交付物 | 本地验收入口 |
| --- | --- | --- |
| M2 — Data Logger | Logger Dockerfile、独立 Logger 部署 Compose，以及根目录支持 Logger 的 `docker-compose.dev.yml`；配置样例、SQLite／凭据持久化卷，以及硬件部署时显式串口设备映射说明。支持本地开发构建和目标 Linux ARM64 镜像。 | 用 Compose 本地构建并启动，再打开说明中的 Logger URL。开发环境默认使用明确标示的合成 P1 来源，不映射宿主机串口。走查现场配置、预览、启动／停止、状态，以及容器重建后的持久性；不要求中心端存在。 |
| M3 — Centralized Server | Server Dockerfile，以及包含 PostgreSQL、迁移／启动处理、持久化存储和 Caddy HTTPS 配置的独立 Server 部署 Compose；在 `docker-compose.dev.yml` 中加入 Server 和隔离的开发 PostgreSQL 服务。Logger 与 Server 可在各自宿主机独立部署。 | 本地构建并启动 Server，打开说明中的管理员 URL，走查登录、现场／设备登记、授权、预置合成读数、筛选及 CSV。开发启动不要求公网域名、生产凭据或 M4 上传器。 |
| M4 — 完整试点 | 更新两端部署配置，接入上传器与回传设置；提供使用真实 Logger／Server 服务及合成 P1 输入的联合开发 Compose 流程。验证实际生产部署说明和目标硬件配置。 | 通过两端页面完成登记、采集、上传、查询及 CSV；在隔离容器中复现断网、重启与积压恢复。Pi／电表实物验收仍是单独的必需检查。 |

每次交付均包含准确的 Compose 构建／启动／停止命令、无真实秘密的配置样例、浏览器 URL、必要的开发凭据／设置步骤、预期页面行为、健康／就绪检查、日志与资源清理说明。开发服务默认仅绑定本机，使用独立 Compose project、网络及可删除的卷／数据；不复用生产配置、外部生产卷或宿主机设备映射。清理只删除本次走查创建的资源。部署配置须保证容器重建后保留应用数据和凭据；销毁卷的清理仅适用于可删除的开发环境。

M1 依据自动化协议／契约检查及委派的命令行验证验收；它没有 UI，不要求所有者重复开发者命令。面向所有者的产品走查从 M2 开始，以 Compose 启动后的浏览器操作为主。本地容器交付随各应用 Milestone 提供，M4 验证完整部署及硬件集成。

各阶段相关检查：

- **M1：** 任意串口分块、CRC 错误、异常输入及缓冲上限、脱敏、UTC 转换、单位、累计精度、单相／三相缺测。选择性复用[交接文档](home-automation-energy-handover.md)中的能力；WarmteLink 默认参数和已有 fixture 不证明电力表兼容性。
- **M2：** 10 秒选取、空窗口、持久化重启、串口重连及资源释放、凭据持久化、已有现场复用、会话切换、清理保留待上传数据、存储耗尽的显式行为。M2 不执行网络上传，新记录保持 pending。使用合成批次和确认测试本地确认／清理原语；真实上传器属于 M4。
- **M3：** 管理员访问、Token 哈希验证及停用、现场授权、已有 UUID 信息处理、批次原子持久化、重试去重、查询与 CSV 一致性。
- **M4：** 离线采集后登记、长时间断网后边采集边补传、上传期间重启、中心端提交后响应丢失、凭据拒收、换现场后的旧会话补传、本地与中心端记录 ID 核对。

开发检查使用隔离服务、临时数据库和合成／脱敏数据。实物验证必须使用专门测试环境，不改动生产服务，也不与现有串口读取程序争用设备。在两款目标树莓派上测量内存、CPU、磁盘写入及持续采集，用合成数据量测试确认至少四周离线容量；没有设备条件的检查标为待验收，不算通过。

M4 的必需检查全部通过后才完成该阶段。交付准确的启动、配置、登记、状态解释、故障排查及清理步骤。MVP 交付后的数周现场观察单独记录。

## 5. 后续路线与文档

1. **图表与确定性分析：** 功率趋势、每日电量、进口／回送总量、覆盖率及缺测。累计量差分遵守有效电表／会话边界，并区分采样峰值与实际最大值。
2. **AI 报告生成与审阅：** 手动选取时间段，计算脱敏统计快照，由独立 worker 生成文字分析，保存快照／模型／提示词版本，审阅后导出 PDF。模型失败不影响采集和数据访问。
3. **Modbus 采集：** 增加独立验证的 profile 和传输方式。DDSU666 历史证据是起点；DTSU666 需要确切型号手册和实物验证。串口 RTU 与 RTU over TCP 分别扩展。
4. **Provisioning 与运维：** 根据实际需要增加自动登记、远程配置、升级和更丰富的 React 界面。网络管理仍在应用之外，除非另行商定。

MVP 页面默认英文。纳入版本管理的项目文档具有语义等价的中英文版本，英文权威；保持架构、路线图、后续任务卡和操作说明的语言对一致。完成证据记录在对应任务／进度文档中，不将本文规划视为已实现。
