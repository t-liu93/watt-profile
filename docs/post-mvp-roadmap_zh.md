## 1. 当前基础与后续目标

MVP 已建立可靠的数据链路：

**现场配置 → P1 采集 → 本地持久化 → 离线积压恢复与上传 → Server 存储、查询和 CSV 导出。**

当前 Server 已提供 M5 分析工作台、图表、衍生统计、管理及原始／CSV 溯源；分析报告与设计辅助仍为后续工作。[M4 结项记录](milestone/m4_zh.md#所有者最终验收与-mvp-结项2026-10-18)区分了所有者验收与未独立记录的测量；本文不重新打开该验收，也不将这些测量标为通过。

Post-MVP 的目标是让内部操作人员和设计人员能够：

1. 判断一次监测的数据是否完整、是否足以分析。
2. 理解现场数周的电网取电、馈电及日内变化。
3. 将可核对的分析结果整理为报告。
4. 在明确必要现场输入后，逐步评估电池与光伏场景。

主线按 **M5 分析工作台 → M6 分析报告** 推进。设备与运维扩展根据实际需求安排，不要求全部等待报告功能完成。

## 2. M5：Server 分析工作台

**目标：将基本数据管理页面升级为日常可用的内部分析工作台。**

### 功能范围

- **工作台与导航**：统一组织站点、分析、设备和登记入口，提供站点搜索、数据概览及分别展示的最近联系／读数时间。
- **核心分析**：进出电功率曲线、每日进出电量、所选时段统计、采样峰值及典型日曲线。
- **数据质量**：展示采样覆盖、缺口和关键字段缺失情况，并能查看相关原始记录。
- **分相诊断**：查看 L1/L2/L3 电压、电流和进出电功率，正确处理单相设备及缺失字段。
- **统一筛选**：按站点、监测会话和时间范围分析，支持日期选择、图表缩放及数值提示。
- **当前观测**：在历史分析之外提供最新读数和可暂停的自动刷新，明确显示数据时间与刷新失败。
- **管理功能迁移**：整合现有登记、站点编辑、设备凭据、授权、原始记录与完整 CSV 导出。
- **界面体验**：支持中英文切换、深浅主题，以桌面分析为主，同时保证较窄屏幕下的基本可用性。

### 技术方向

采用 **React、TypeScript、Vite**。构建产物随 Server 镜像交付，由现有 FastAPI 应用同源提供；继续使用 PostgreSQL 和现有部署方式。

统计与聚合在 Server 完成，按查询范围返回适合展示精度的数据，避免依赖浏览器下载全部记录后计算。保留原始数据作为核对依据。

M5 沿用现有 Logger 上传契约。

### 完成标准

内部用户能够从站点入口查看数周数据，识别主要取电／馈电规律和数据缺口，检查分相指标，并回到原始记录核对。原有管理与导出流程继续可用。

验证统计正确性、四周合成数据量下的查询与图表响应、双语界面、容器交付和已有上传流程回归。[M5 设计](milestone/m5_zh.md)记录具体检查、实测结果和所有者最终验收。

**本阶段不包含：** AI 报告、PDF 导出、电池/PV 容量建议、客户账号或远程设备管理。

## 3. M6：分析报告

**目标：将分析工作台中的结果整理为可追溯、可供内部人员审阅和导出的报告。**

分两步交付：

1. **确定性统计报告**：选择站点、会话与时间范围，生成包含监测概况、数据质量、关键统计和图表的报告。
2. **AI 解读与审阅**：基于确定性统计描述用电特征和待核查事项，支持内部审阅及 PDF 导出。

报告保存生成时的统计输入、分析版本，以及适用的模型和提示词版本。后续补传数据不静默改变既有报告。

独立 worker 通过 OpenRouter 调用模型，使用不含现场身份标识的统计输入。模型和接口能力在本阶段设计时验证；生成失败或服务不可用不得影响采集、接收、查询和已有报告访问。

报告首先解释观测结果。具体设备选型、容量及收益建议，需要后续定义额外输入与计算方法。

## 4. 按需求推进的扩展方向

以下方向暂不分配固定 Milestone 编号或交付日期。

| 方向 | 主要内容 | 启动条件 |
| --- | --- | --- |
| **设备与采集扩展** | Modbus TCP、其他 P1 profile，以及后续独立的串口 RTU／RTU over TCP 支持 | 明确的现场需求、确切型号资料和适当的验证条件 |
| **电池/PV 设计辅助** | 场景对比、容量与运行策略分析，必要时增加经济性评估 | 已明确现场输入、发电数据、设备约束及计算假设 |
| **运维与部署** | 恢复演练、诊断改进、自动登记、远程配置和升级 | 实际维护成本或部署数量需要 |
| **容量与性能** | 查询优化、预聚合、存储组织与部署扩展 | 实测数据量、延迟或资源消耗证明有需要 |

标准 Modbus TCP 为首个 Modbus 传输方向。DDSU666 的历史实现可作参考；DTSU666 等设备需要确切型号资料与实物验证。

宿主机网络、Wi-Fi、DHCP、VPN、证书和反向代理管理继续保持现有边界，除非后续明确决定纳入。

## 5. 分析与交付原则

- **统计可核对**：电量依据累计读数，遵守有效来源、会话和电表边界；无法可靠计算或归属的部分明确标注。
- **保留数据限制**：缺失不补零，图表不掩盖缺口；十秒采样峰值不等同于真实瞬时最大值。
- **明确测量含义**：P1 提供电网取电和馈电。有光伏时，不能直接据此认定住宅总用电、光伏总发电或自用率。
- **时间口径一致**：存储与接口时间保持 UTC；首版日统计默认使用 `Europe/Amsterdam`，正确处理夏令时切换。
- **状态不作过度推断**：区分设备联系与读数新鲜度；缺少生命周期事件时，不从沉默推断会话完成或准确在线率。
- **验证后交付**：每个阶段包含相应镜像、配置、升级说明和隔离环境验收；使用合成或脱敏数据，不以规划代替实现证据。
