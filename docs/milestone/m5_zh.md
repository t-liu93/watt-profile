## 1. 目标与 Agent 使用方式

将现有 Server 管理页面升级为内部分析工作台。操作人员能够查看一个站点、一次监测 session 的数周读数，理解电网取电／馈电规律，检查缺口和分相指标，并通过原始记录核对结果。

将本文和任务 ID 交给 Agent。实现前阅读 [Agent Guide](../../AGENTS_zh.md)、[Post-MVP 路线图](../post-mvp-roadmap_zh.md)、相关 [M1 契约](m1_zh.md)、[M3 Server 契约](m3_zh.md)、[M4 结项记录](m4_zh.md#所有者最终验收与-mvp-结项2026-10-18)及当前源码。第 2 节定义共享契约，第 3 节提供有序原子任务，第 4 节定义检查和验收记录。后续 M5 决策和证据继续保留在本文及英文镜像中。

交付站点搜索与管理、按 session 分析、功率趋势、累计与每日电量、采样峰值、平均日、分相诊断、数据质量检查、最新读数、中英文界面、深浅主题和容器交付。保留登记、设备凭据、授权、原始查询和完整 CSV 导出。

沿用 PostgreSQL、FastAPI、管理员认证和 Logger 上传协议。本阶段不包含 AI、报告、PDF、电池/PV 容量建议、客户账户和远程设备管理。不重新打开 M4/MVP 验收。本文不启动委派编排，也不授权部署、发布或生产访问。下文新增模块、接口、测试、前端文件和命令均为计划交付项，不代表现有功能。

## 2. 共享实现契约

### C1. 导航、选择与默认行为

登录后进入**站点总览表格**，显示名称、地址、读数数量、最新读数时间和站点入口。支持按显示名称／地址搜索或精确 UUID 查询。主导航包含站点、设备和登记。

| 站点标签页 | 内容 |
| --- | --- |
| 概览 | 期间统计、功率曲线、每日电量、质量摘要和最新读数 |
| 用电规律 | 平均日曲线及日期分组 |
| 分相诊断 | 电压、电流、功率三个对齐图表 |
| 数据质量 | 覆盖情况、缺口、字段有效性和问题记录 |
| 原始记录 | 分页记录、完整详情和完整 CSV |
| 设置 | Server 显示名称、站点资料和相关管理入口 |

- 默认选择**最近有读数的 session**，按最大 `received_at` 排序；并列时依次按 `started_at`、session UUID 降序确定。历史 session 可选。没有读数时显示明确空状态，不伪造默认 session。
- 每次只分析一个 session，不合并多个 session。
- 初始七日范围从最新读数本地日期之前第六日的 Amsterdam 零点开始，起点不早于 session 开始；排他终点为最新读数之后一个微秒，确保包含最新读数。
- 日期选择支持完整本地日。单次分析最多涉及 **31 个 Amsterdam 日历日期**，末日按排他终点规则计算。
- 最近七日模式手动刷新时重新解析最新 session 上下文／范围；自定义日期刷新保留边界。最新读数自动刷新不切换 session、不改变分析范围。
- 原始查询仍可跨 session；原始查询和完整 CSV 不受 31 日分析上限限制。
- URL 保存标签页、session、范围模式和已解析／自定义边界。刷新、前进后退和复制链接均可用。功率图局部缩放不改变期间统计。

### C3. 前端技术栈与组件来源

使用 React、TypeScript、Vite、Tailwind CSS、**基于 Radix 的 shadcn/ui**、按需引入的 Apache ECharts、React Router、显式中英文翻译资源和统一同源 fetch 客户端。应用状态和请求归属由 React 管理，暂不增加全局状态／查询框架。Node.js 24 仅用于开发和构建。M5-09 在功能开发前选定具体工具／依赖版本并写入锁文件，普通构建按锁文件执行。

前端工程位于 `frontend/`。仓库提交页面、业务组件、包装层、主题、配置、准备脚本和锁文件。**上游组件源码不提交到 Git。** 生成的组件／辅助文件和下载的 registry 内容被忽略，禁止手工修改；自定义样式和行为放在受跟踪的主题／包装层中。

| 锁文件 | 职责 |
| --- | --- |
| `package-lock.json` | npm 精确依赖树，包括工具，使用 npm 原生完整性校验 |
| `ui-components.lock.json` | 项目定义的 registry 资源、递归组件依赖、固定来源和 SHA-256 锁文件 |

组件锁文件记录格式版本、Radix 基础／样式选择、上游完整 commit、资源 URL 和 SHA-256、组件依赖关系、生成配置指纹和生成文件 SHA-256。npm 继续使用原生完整性格式，不另写一套 npm 包哈希机制。

准备与升级规则：

1. 开发时使用固定版本的 shadcn CLI 查看／选择组件。显式 `ui:update` 操作解析上游完整 commit 并生成候选组件锁文件；依赖变更在同一候选改动中更新 npm 锁文件。
2. `ui:prepare` 下载、校验锁定的可安装 registry 资源，按版本化、显式的路径／import 别名转换生成文件。未支持的 registry 内容直接拒绝，不静默应用任意工程修改。上游已提交可安装 registry JSON，无须构建整个上游仓库。
3. 解析并锁定完整的递归组件／辅助依赖图及必要生成输入。只固定顶层组件不够：shadcn 依赖不会继承顶层 ref，每一项使用的资源均有自己的固定来源和校验值。
4. 普通准备不调用浮动版本 CLI、不解析 `latest`、不额外安装包、不修改受跟踪配置／锁文件。npm 依赖使用 `npm ci` 安装，`ui:verify` 按锁文件校验生成结果和配置。
5. 走查前从干净环境还原候选版本。通过后冻结**同一份候选锁文件**，不在走查后重新获取一次上游版本。
6. 来源不可用、存在未锁依赖或输入／输出哈希不一致，准备／构建直接失败。更新锁文件是经过验证的显式开发操作，不由 CI 自动修复。

官方参考：[registry item 格式](https://ui.shadcn.com/docs/registry/registry-item-json)、[依赖 ref](https://ui.shadcn.com/docs/registry/github#dependency-refs)、[上游 registry 结构](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/README.md)和 [npm 锁文件](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/)。这些资料解释上游机制；项目组件锁文件为自行定义的格式。

### C4. 语言、认证状态与刷新

- 导航、登录、表单、校验、错误、图表标签和空状态全部提供双语。首次按浏览器语言选择中文，否则英文；默认深色，保留现有 `watt-profile-theme` 偏好键。
- 浏览器存储仅持久保存语言／主题，不保存凭据、登记摘要或业务数据。导航／筛选状态放在 URL。
- 最新读数／联系信息每 **10 秒**刷新，可暂停；后台暂停、无重叠轮询，认证过期后停止。不轮询历史图表／统计接口。
- 历史分析仅在条件变化或手动刷新时请求。取消过时请求，阻止旧站点／session／范围的迟到结果覆盖当前状态。
- 刷新失败保留上次成功结果，并显示其时间和明确失败状态；没有旧结果时显示错误／重试状态。
- 认证过期后取消请求、清除敏感临时状态并返回登录；不自动重试修改操作。

### C5. Server 显示名称与数据库升级

站点和设备增加 Server 专用 `display_name`：默认 `""`，最多 100 个字符，单行，禁止控制字符，允许重名和空名称。站点名称为空时依次回退到地址、短 UUID；设备回退到短 UUID，完整 UUID 始终可查看。

站点管理创建／编辑／读取支持名称，设备支持名称编辑。显式 null 不合法，空字符串用于清空。名称不改变身份、Token、授权、session／source 描述、登记摘要、canonical Snapshot 字节／hash 或 CSV。Logger 登记摘要保持原有字段，重复登记不覆盖已有名称。沿用站点资料编辑行为和修改锁。

新增 `server_0002`，添加名称和站点／session／时间分析索引。**先固定 `server_0001` 的初始结构**：它当前引用实时 schema metadata，直接添加新列会让全新安装重复创建。启动允许已知旧版本升级；未知／更高版本仍失败且不重置。验证全新安装、从 `server_0001` 升级、重复／并发启动，以及读数和凭据保留。实现验证不操作生产迁移。

### C6. 时间、数值含义与读取一致性

- 分析使用 Snapshot **`received_at`，即 Logger 收到读数的时间**。可用时分别展示 Server 入库时间和 meter 时间，不用它们替代分析时间轴。
- API 接收带时区时间，归一化 UTC，采用 `[received_from, received_before)`。每日和平均日按 `Europe/Amsterdam` 分组，处理 23／25 小时日期。
- session 按最大读数时间选择，不按最后上传顺序。每个分析响应使用一个只读 REPEATABLE READ 事务，概览统计／图表共享同一次读取快照。
- 不同响应可能看到新上传／补传数据。返回计算时间、请求范围、实际首末读数时间和数量，不声称跨请求冻结数据。
- 聚合读取写入时已验证的指标投影，不把整月完整 Snapshot 加载进 Python／浏览器内存。原始详情、CSV 和最新完整读数继续验证 canonical／hash／投影，聚合不代表全库完整性审计。
- 同步数据库操作离开事件循环，连接／事务生命周期短。
- 计算保留 Decimal／NUMERIC，并为允许的数据保留足够精度。API 测量值为十进制字符串，缺失为 `null`，零为有效值。显示时舍入，计算不提前舍入。图表只转换有限且可表示的数值，否则保留精确文本入口并将绘图值标为不可用。

### C7. 电量、功率与每日统计

**累计电量。** 取电、馈电分别计算；每个方向的有效端点必须同时有 T1 和 T2。所选 session／source 内按 `(received_at, device_id, record_id)` 排序，比较相邻有效端点。

- 任一 tariff 累计值下降时排除该区间，记录一次重置／回退，从后端点重新建立基线。不允许只比较合计值而掩盖某个 tariff 的回退。
- 跳过缺少累计字段的端点。有效且不下降的端点可以跨采样缺口计算期间电量，但保留缺口说明和实际端点范围。
- 仅使用所选范围内的端点；少于两个有效端点为不可计算，不返回零。不做功率积分、插值或缺失电量估算。

**每日电量。** 完全属于同一 Amsterdam 日期的累计区间计入该日；右端点恰好为下一日本地零点时归属前一日。真正跨越日期的区间计入单独的**跨日未分配电量**，不按比例拆分。

返回实际累计端点范围、有效区间数和不完整原因。每日数值标为已记录区间电量，不把部分数据称为整日电量。每个方向都必须满足：

**每日已归属电量之和＋跨日未分配电量＝期间已计算电量。**

**功率与峰值。** 每个时间桶返回平均值／最小值／最大值和有效数量，每个序列最多约 2,000 桶。缩放请求更细数据，十秒级短范围可显示原始点。空桶保持 null，不补零；缺口处断线，已填充桶内存在缺口也要标记。采样峰值独立从原始投影值计算，返回时间和原始记录定位，并列取确定排序最早的读数。馈电仅在图表展示为负值，API 保持非负。

使用**采样峰值**，不称为真实瞬时最大值。电网取电／馈电不能直接确定家庭总用电、光伏总发电或自用率。

### C8. 数据质量、平均日与分相

**数据质量。** 名义预期数为所选区间实际秒数除以十并向上取整。显示 `实际数／预期数`，最多 100%，超出数量单列。它是名义采样比例，不是在线率。

- 相邻读数超过 30 秒时，缺口从前一读数之后十秒开始，到后一读数结束。
- 范围边缘距首／末读数超过 30 秒时记录首／尾未覆盖区间，尾部缺失从末读数之后十秒开始。没有读数时将整个范围标为无记录。
- 返回各指标有效／缺失数量，分别统计取电／馈电累计端点有效性。
- 只汇总已保存的质量问题，支持原始记录定位；有意隐私脱敏单独列示。不虚构 CRC 拒绝总数、停机原因、session 完成状态或在线状态。
- L2／L3 缺失表示“未提供”，不直接判定设备故障。

**平均日。** 按 Amsterdam 本地时间划分 15 分钟槽。每个指标先计算每个日期／槽的样本平均，再对合格日期等权平均。一个日期／槽的有效指标数量达到该槽完整实际时长对应名义数的 80%，才参与该指标平均。返回参与日期数，没有合格日期时返回 null。支持全部日期、周一至周五、周六／周日。秋季重复时段在该日期合并为一个槽，按双倍实际时长判断有效性；春季不存在的槽不补值。部分日期不足的槽不参与。

**分相。** 电压、电流、功率分别成图，对比 L1／L2／L3，共用时间轴／图例，单位分开。功率默认取电，可切换馈电；复用功率分桶和缺口规则。不增加未经定义的电压合格判断或故障告警。

### C9. HTTP 接口与兼容性

沿用 `/api/admin/v1`、现有成功／错误信封、管理员 Cookie、CSRF、Host／Origin 检查和 `no-store` 行为。登录保持现有表单 POST 和跳转语义。Bearer 凭据不能认证管理接口，不弱化现有 body 上限和固定安全错误。

| 方法与路径，省略公共管理前缀 | 契约 |
| --- | --- |
| `GET /workspace/sites` | 分页站点摘要，按名称／地址字面子串搜索或精确 UUID 查询，返回读数数量和最新读数时间 |
| 现有站点管理接口 | 增加 Server 显示名称，旧请求保持有效 |
| `PATCH /devices/{device_id}` | 仅编辑显示名称 |
| `GET /sites/{site_id}/analysis/sessions` | 分页 session 上下文、首末读数、数量和默认选择信息 |
| `GET /sites/{site_id}/analysis/overview` | 同一读取快照内的统计、电量、功率曲线、每日电量和质量摘要 |
| `GET /sites/{site_id}/analysis/power` | 功率图局部缩放数据 |
| `GET /sites/{site_id}/analysis/typical-day` | 平均日槽和日期分组 |
| `GET /sites/{site_id}/analysis/phases` | 分相序列 |
| `GET /sites/{site_id}/analysis/quality` | 质量统计及独立分页的缺口／问题记录定位 |
| `GET /sites/{site_id}/analysis/latest` | 所选 session 的最新完整读数、对应设备认证联系时间及站点最新读数时间 |

上下文解析后，历史分析请求显式传入 `session_id`、`received_from` 和 `received_before`。响应共同包含所用范围、时区、计算时间、数量及实际首末读数时间；曲线另报分辨率，统计另带不可计算原因。最新观测独立于历史范围，明确标识 session／设备；设备联系可能来自所选 session 之外的活动。

- session 不存在或属于其他站点返回 404；非法区间、超过 31 日期返回固定安全 422。缩放边界必须在一并传入的全局分析范围内。
- 新分页结果默认 50，最大 100。质量缺口和问题记录各有分页参数，完整 Snapshot 使用现有详情接口。
- 每进程最多两个重历史分析并发，事务内 statement timeout 为十秒。繁忙、超时和存储不可用返回安全 503。最新读数轮询保持轻量，不占重分析名额。
- 分析名额与原有两个 CSV 名额独立；异常、取消和完成都释放资源，保留现有有限连接池。
- 现有 ingest、原始查询和 CSV 的认证、筛选、排序、十进制表示和完整流式契约不变。

已实现查询参数名（M5-08）：`/workspace/sites` 接受互斥的 `q` 或 `site_id`，以及 `offset`／`limit`。功率／分相曲线接受成对的 `zoom_from`／`zoom_before`，边界必须位于必传全局范围内。分相使用 `direction=import|export`，默认 import。质量页分别使用 `gap_offset`／`gap_limit` 与 `problem_offset`／`problem_limit`。平均日可选 `group=all|weekday|weekend`，省略时返回三组。最新读数只需 `session_id`，不传历史范围；响应分别保留 `snapshot`、`ingested_at`、`device_last_authenticated_contact_at` 与 `site_latest_reading_received_at`。
