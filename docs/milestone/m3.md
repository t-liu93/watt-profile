## 2. Shared implementation contracts

### C1. Runtime, configuration and boundaries

Use Python 3.12, existing FastAPI/Uvicorn, SQLAlchemy 2, Alembic and Jinja2, adding Psycopg 3 with its binary distribution. Regenerate runtime/development locks and package server migrations/templates/static assets. Keep the existing Logger build working. Use PostgreSQL 17 and Caddy 2 image families; M3-08 fixes concrete available image versions in Compose and records them, rather than using `latest`.

Planned modules under `src/watt_profile/server/`: settings/bootstrap, storage (schema/migrations/repositories), registration, ingest, queries/export, auth/app, templates/static. Entrypoints: `python -m watt_profile.cli.server` and `python -m watt_profile.cli.server_admin`. Shared `contracts` must not import either application. Keep repository/service operations HTTP-independent and use short-lived SQLAlchemy sessions, never shared across threads. Synchronous database work runs off the event loop; streaming exports own a separate connection for their lifetime.

| Setting | Contract |
| --- | --- |
| `WATT_SERVER_DATABASE_URL_FILE` | Required private UTF-8 file containing the SQLAlchemy `postgresql+psycopg` URL; strip one terminal newline; never log it |
| `WATT_SERVER_ADMIN_USER` | Required, 1–64 characters |
| `WATT_SERVER_ADMIN_PASSWORD_FILE` | Required private password file, 16–256 characters after removing one terminal newline; no production default |
| `WATT_SERVER_PUBLIC_ORIGIN` | Required HTTP/HTTPS origin without userinfo/path/query/fragment; validates browser Origin and trusted host |
| `WATT_SERVER_HOST`, `WATT_SERVER_PORT` | Defaults `0.0.0.0`, `8080`; Compose controls external exposure |
| `WATT_SERVER_COOKIE_SECURE` | Default true; false only for explicit development or owner-managed tunnel HTTP |

Run one Uvicorn worker without reload. Use a finite DB pool (5 connections plus 5 overflow), pool checkout timeout 5 seconds, and transaction-local lock/statement timeouts (5/30 seconds for ordinary operations; export uses C6). Bootstrap validates configuration, obtains a PostgreSQL advisory migration lock, upgrades to the known head, releases the lock, and becomes ready. A newer/unknown revision or migration failure fails startup without reset. Imports create no files, connections or credentials. Shutdown stops admission, closes streams and disposes the pool; allow 30 seconds in Compose.

Provide `server_admin generate-password --output PATH` (0600, random `token_urlsafe(24)`, exclusive creation) and `server_admin migrate` using the same settings/migration lock. Password change requires application restart. Secret-file parents are private, container mounts read-only, process umask 0077. Do not expose SQL text with bound values, connection strings, request bodies or credentials in errors/logs.

### C2. PostgreSQL storage and transaction rules

Implement all Server columns, nullability, defaults, named keys/checks/indices in M1 C5, beginning with independent revision `server_0001`. No Logger-only config, collection state, fingerprint or upload-state columns. PostgreSQL timezone is UTC. NUMERIC remains unconstrained, nonnegative and finite; validate UUID versions/variants, JSON roots, canonical UTF-8 byte length, hashes and composite ownership. Revalidate models and canonical/projection agreement on insert and load. Canonical TEXT preserves decimal scale, nulls and array order; JSONB and numeric projections are not hash inputs.

Repositories own transaction boundaries. Provide typed operations for registration preview/commit, site edits/listing, credential/grant management, credential authentication/contact, atomic ingest, status, reading pages/details and export iteration. Never return ORM objects needing a closed session. Snapshot/descriptor content is immutable. No cascade deletion, historical delete endpoint, retention job or automatic purge; accepted snapshots remain for at least one year, independent of credential/grant changes and Logger cleanup.

Use database transaction-scoped advisory locks to coordinate mutations even across application connections: fixed shared namespace with keys derived deterministically from each UUID (not Python's randomized hash). Acquire locks in this order: device, site, session, source; sort UUIDs within a class. Hash collisions may serialize unrelated work but must not weaken correctness. Registration, site edits, credential/grant changes and ingest use the same relevant locks; schema migration has a distinct lock namespace. PK/UNIQUE/FK constraints remain the final authority. Inserts that encounter existing descriptor/record keys must load and compare immutable content, not blindly ignore conflicts. Map concurrent credential uniqueness conflicts to a safe registration conflict.

An ingest transaction rechecks enabled credential and grant while holding device/site locks; revocation uses those locks too. Whichever transaction acquires the locks first takes effect first: an already accepted batch may finish before revocation, but later acceptance cannot use the revoked permission. Tests use independent real PostgreSQL connections and barriers, not only sequential retries. Lock timeout, transient connection failure and database unavailability produce safe retryable failure; do not acknowledge uncommitted data.

### C3. Administrator authentication and HTTP conventions

One deployment-owned administrator account, separate from Logger/operator and Bearer credentials. Follow M2's authentication behavior with independent server code/state and cookies `watt_server_session`/`watt_server_login`: opaque random session IDs, at most 32 sessions, eight-hour expiry, logout/restart revocation, pre-login CSRF expiring after 15 minutes, constant-time credential comparison and bounded login throttling (10 attempts per remote address per minute, at most 1,024 addresses). No account database, roles or password-reset UI. Reuse pure helpers only if Logger behavior remains covered by regression tests; do not import the Logger application.

Cookies are HttpOnly, SameSite=Lax, path `/`, with configured Secure. Validate CSRF on login and every authenticated mutation, including registration preview, and same-origin Origin when supplied. JSON sends `X-CSRF-Token`; forms send a hidden token. No CORS. Escape rendered values; authenticated pages/API/export use `Cache-Control: no-store`. Never echo input-bearing validation exceptions. Session cookies do not authenticate ingest, and Bearer Tokens do not authenticate management.

Configure Caddy as the only public entry point in standalone deployment; app/DB ports are unpublished. Strip/replace untrusted forwarding headers at that boundary. Do not enable wildcard forwarded-header trust in Uvicorn. Application origin decisions use configured public origin; login throttling may use the direct proxy peer in M3 (a conservative shared limit), rather than trusting arbitrary client headers. Direct local development uses the actual peer. Disable access logging of query strings/request bodies; logs may include route template, status and fixed error code.

Page routes: `GET/POST /login`, `POST /logout`, protected `GET /`, `/sites/{site_id}`, `/devices/{device_id}`. Unauthenticated pages redirect to login; management APIs return 401. Management prefix `/api/admin/v1`; success is `{"data": ...}` except 204, failures `{"error":{"code":"...","message":"fixed safe text"}}`. Use 403 for CSRF, 404 for absent objects, 409 for registration conflicts, 422 for invalid inputs and 503 for unavailable storage. Define fixed messages in code. Management JSON rejects extra keys; management bodies are capped at 32 KiB before JSON parsing. Ingest retains its separate M1 envelopes and bounds.

`GET /health/live` checks application liveness; `/health/ready` checks initialized migration state and DB availability with a bounded lightweight query. Both unauthenticated responses contain only a boolean; ready returns 503 before initialization/during shutdown or DB failure. Empty data or disabled devices are valid ready states.

### C4. Registration, credentials and authorization

Registration summary is a JSON object with exactly `site_id,address,description,device_id,token`, matching the current Logger API data object without its `data` envelope. UUIDs are v4; address/description retain M2's 500/2,000-character limits and may be empty or multiline. Token must match the Logger's persisted `token_urlsafe(32)` format (43 URL-safe ASCII characters). Reject duplicate JSON keys, malformed/extra fields and oversized input with fixed safe errors.

M3-07 changes the Logger's copied textarea content to formatted JSON while retaining readable labels on screen. The local registration API and Token generation remain unchanged. No legacy labeled-text parser is required. Neither page stores the summary in localStorage/sessionStorage or a URL; clear it on submit success, cancel, navigation/logout, or authentication expiry. Preview masks the Token and never returns it from the server.

Preview reports which site/device/credential/grant would be created or reused, and existing server address/description when they differ. It performs no writes. Commit takes the original validated summary, re-evaluates under locks and performs all registration writes in one transaction. It never overwrites existing site metadata, replaces credentials or restores a disabled credential. A changed preview is not a promise of unchanged state; submit returns the actual applied/reused outcome and current metadata.

Same device/Token/site registration is idempotent. Reuse a known device with its same enabled Token at an additional site, preserving earlier grants. Token hash belonging to another device, a disabled matching Token, or a new Token for an already credentialed device gives 409 without any partial site/device creation. Existing devices with no credential may receive their first credential. Store SHA-256 of the high-entropy Token only; never return digest or Token in ordinary management output. Rotation/re-enablement is outside M3. Devices/sites may be created separately by the endpoints below; no address-based identity matching.

| Method and relative management path | Input → result |
| --- | --- |
| `POST /registrations/preview` | Summary → existing metadata and `create/reuse` actions for site/device/credential/grant; masked credential indicator only |
| `POST /registrations` | Summary → site/device/credential IDs, current metadata, applied/reused actions |
| `GET /sites` | Optional `site_id` exact UUID or `q` literal case-insensitive address substring (mutually exclusive), `offset=0,limit=50` (1–100) → `{items,total}`, ordered by site UUID |
| `POST /sites` | `{site_id,address,description}` → created/existing site; caller supplies UUID, existing metadata unchanged |
| `PATCH /sites/{site_id}` | Nonempty subset of address/description → explicit metadata edit |
| `GET /devices`, `POST /devices` | Pagination as sites / `{device_id}` → list or created/existing device |
| `GET /devices/{device_id}` | → device status, credential IDs/created/disabled times and granted site IDs; no hashes |
| `POST /devices/{device_id}/credentials` | `{token}` → first or same enabled credential ID; same conflicts as registration |
| `POST /devices/{device_id}/credentials/{credential_id}/disable` | `{}` → credential state; already disabled is a no-op |
| `PUT /devices/{device_id}/sites/{site_id}` | `{}` → grant; both objects must exist; idempotent |
| `DELETE /devices/{device_id}/sites/{site_id}` | → 204; absent grant is a no-op for existing objects |

Site edits and destructive access changes require UI confirmation where appropriate: disable/revoke explains that pending Logger records will stay pending and historical readings remain. Adding a new-site grant never removes old grants. Device IDs and site UUIDs cannot be edited.

### C5. Ingest and contact status

Implement M1 C6 exactly: `POST /api/v1/ingest/batches`, Bearer Token, JSON, schema v1, maximum 200 records, 16,384 canonical bytes per snapshot and 4,194,304 received body bytes. Bound streamed reads even without Content-Length; reject compressed bodies. Use existing `validate_upload_body`, canonical codec and error types; unsupported media/encoding uses safe `invalid_payload`. Do not leak framework validation detail or include records in logs.

Authenticate using the Token hash and enabled credential. Valid authentication records `last_authenticated_contact_at` in a short separate transaction, using a monotonic database update (`greatest` with the existing value). Unknown/disabled credentials never update it. Validation failure, device mismatch or unknown/unauthorized site may still count as authenticated contact; entry-point oversize rejection need not. If contact storage fails, return 503. This timestamp proves authentication, not acceptance or measurement freshness.

Then validate device identity and the complete batch, and atomically recheck authorization/create missing point/session/source/insert readings under C2 locks. Devices/sites/grants must already exist; point derives from the site UUID. Compare all immutable descriptor fields, including descriptors accompanying duplicate-only batches. Equal record key/hash is a duplicate, unequal hash is whole-batch `record_conflict`; mismatched descriptors are `descriptor_conflict`. A new row followed by any conflict leaves neither new rows nor newly created descriptors committed. Cross-device attempts to reuse session/source IDs fail without rewiring them.

Only after successful commit return M1's 200 confirmation with all request record IDs in request order, including existing duplicates. Use M1's fixed error codes/statuses for 401/403/409/413/422/503. Lost response after commit is exercised by retrying the same batch and confirming unchanged row count; actual Logger response-loss recovery belongs to M4. A failure after commit must not be described as a known rollback.

### C6. Status, queries and complete CSV

Site list/detail displays UUID/address/description, accepted reading count, latest accepted `received_at`, and currently authorized devices. Device views separately display `last_authenticated_contact_at` and maximum accepted `received_at` across history. Missing values display “Unavailable”; no invented online/offline threshold. Site timestamps come from that site's readings, not whichever device grant was added last. Server session lists expose immutable descriptors only, with no fabricated open/completed state.

| Method and relative management path | Contract |
| --- | --- |
| `GET /sites/{site_id}` | Site metadata/status and authorized device IDs |
| `GET /sites/{site_id}/sessions` | Pagination as C4, ordered by `started_at,session_id`; optional device filter |
| `GET /sites/{site_id}/readings` | Filters below plus `offset=0,limit=50` (1–200) → `{items,total}`; items are complete M1 Snapshots |
| `GET /sites/{site_id}/readings/{device_id}/{record_id}` | Complete Snapshot belonging to that site, otherwise 404 |
| `GET /sites/{site_id}/readings.csv` | Same filters, no pagination → complete streaming CSV attachment |

Reading filters: optional `session_id`, `device_id`, `received_from`, `received_before`. Times require aware ISO 8601 input, normalize to UTC, and use inclusive start/exclusive end; when both supplied require start < end. A valid unmatched session/device filter returns empty results; malformed UUID/time is 422. Default no time restriction. Order ascending by `(received_at,device_id,record_id)`; a page's total/items share one read snapshot. UI labels inputs UTC and never silently interprets local time. It shows common metrics in the table, all 18 metrics plus sanitized fields/quality in detail, and exports all filtered results rather than only the visible page.

Use one filter parser/predicate builder for table and export. Read canonical Snapshot text and validate it before serializing; preserve exact decimal-string scale. Export runs in its own read-only REPEATABLE READ transaction, fetches at most 500 rows per chunk using a server-side cursor, and sets a 30-minute statement timeout. No row cap, temporary server file, background job or in-memory full-result buffering. Limit to two concurrent exports per process; excess requests return a fixed 503 before streaming. Client cancellation, timeout, completion and any generator exception close cursor/transaction/connection and release the slot. An error after headers closes an incomplete download, never appends an error row or claims completion. This is synchronous, not resumable export.

CSV is UTF-8 without BOM, comma-separated, CRLF rows with standard CSV quoting and a fixed safe filename `watt-profile-readings.csv`. Columns in order: `schema_version,device_id,record_id,site_id,session_id,source_id,measurement_point_id,meter_time_raw,meter_time_utc,received_at,sampled_at`, then the 18 metric names in M1 C5 table order, then `fields,quality`. Nested columns are compact canonical JSON with nulls/list order preserved; scalar nulls become empty cells, real zero remains zero, times use M1 UTC serialization. No site free text, Token, fingerprint, internal hash, canonical duplicate or ingestion timestamp. All strings originate from validated Snapshot grammar, not arbitrary spreadsheet formulas. Empty results export a header only. Separate query/export requests may observe newly accepted data; consistency means matching filters/representation and one stable snapshot per request, not a cross-request frozen dataset.
