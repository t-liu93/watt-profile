## 2. Shared implementation contracts

### C1. Navigation, selection, and defaults

After login, open a **site overview table** with display name, address, reading count, latest-reading time, and a site link. Search by display name/address or exact UUID. Main navigation provides sites, devices, and registration. Ordinary site/device/initial-credential onboarding uses Logger registration only; list pages link to registration instead of exposing standalone UUID creation or first-Token forms (owner-approved M5-UI-04). Existing-object administration and backend APIs remain available.

| Site tab | Content |
| --- | --- |
| Overview | Period statistics, power curves, daily energy, quality summary, and latest readings |
| Usage patterns | Average-day profiles and date groups |
| Phase diagnostics | Three aligned voltage, current, and power charts |
| Data quality | Coverage, gaps, field validity, and problem records |
| Raw readings | Paginated records, complete details, and complete CSV |
| Settings | Server display name, site metadata, and related administration |

- Select the **most recent session with readings**, ordered by maximum `received_at`; break ties by `started_at`, then session UUID, descending. Historical sessions remain selectable. No readings means an explicit empty state, not a fabricated default session.
- Analyze one session at a time; do not combine sessions.
- The initial seven-day range starts at Amsterdam midnight six dates before the latest reading's local date, clipped to the session start. Its exclusive end is one microsecond after the latest reading, so that reading is included.
- Date selection supports complete local days. An analysis request may intersect at most **31 Amsterdam calendar dates**; count the final date using the exclusive-end convention.
- Manual refresh in recent-seven-days mode resolves the latest session context/range again. Refreshing a custom date range preserves its boundaries. Automatic latest-reading refresh does not switch sessions or change the analysis range.
- Raw queries may still cross sessions. Neither raw queries nor complete CSV inherit the 31-day analysis limit.
- The URL preserves tab, session, range mode, and resolved/custom boundaries. Reload, browser history, and copied links work. Power-chart zoom is local and never changes period statistics.

Use React, TypeScript, Vite, Tailwind CSS, **shadcn/ui with the Radix base**, selectively imported Apache ECharts, React Router, explicit English/Chinese translation resources, and a shared same-origin fetch client. Place all custom styling and behavior in tracked theme/wrappers.

| Lockfile | Responsibility |
| --- | --- |
| `package-lock.json` | Exact npm dependency tree, including tools, with npm-native integrity verification |
| `ui-components.lock.json` | Project-defined lock for registry resources, recursive component dependencies, immutable sources, and SHA-256 checks |

The component lock records format version, Radix base/style selection, full upstream commit, resource URLs and SHA-256 values, component dependency edges, generation-configuration fingerprint, and generated-file SHA-256 values. Keep npm's native integrity format rather than replacing it with a custom npm hashing scheme.

Preparation and upgrade rules:

1. In development, use the pinned shadcn CLI to inspect/select components. An explicit `ui:update` operation resolves a full upstream commit and creates a candidate component lock; dependency changes update the npm lock in the same candidate change.
2. `ui:prepare` downloads the locked installable registry resources, verifies them, and materializes generated files using versioned, explicit path/import-alias transformations. Reject unsupported registry content instead of silently applying arbitrary project changes. Upstream already commits installable registry JSON; rebuilding its whole repository is unnecessary.
3. Resolve and lock the complete recursive component/helper dependency graph and any required generation inputs. Top-level pinning alone is insufficient: shadcn dependency refs are not inherited. Every consumed resource must have its own fixed source and checksum.
4. Ordinary preparation does not invoke a floating CLI, resolve `latest`, install additional packages, or modify tracked configuration/lockfiles. Use `npm ci` for npm dependencies. `ui:verify` checks generated outputs and configuration against the lock.
5. Recreate the candidate from a clean environment for walkthrough. On acceptance, freeze **that same candidate lock**; do not fetch a fresh upstream version after walkthrough.
6. Unavailable sources, unlocked dependencies, or input/output hash mismatches fail preparation/build. Updating a lock is an explicit development operation followed by verification, never an automatic CI repair.

Official references: [registry item format](https://ui.shadcn.com/docs/registry/registry-item-json), [dependency refs](https://ui.shadcn.com/docs/registry/github#dependency-refs), [upstream registry structure](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/README.md), and [npm lockfiles](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/). These references explain upstream mechanisms; the project component lock is our own format.

### C6. Time, numeric meaning, and read consistency

- Analysis uses Snapshot **`received_at`: the Logger's reading-receipt time**. Display Server ingestion time and meter time separately when available; do not substitute either as the analysis axis.
- API inputs are timezone-aware, normalized to UTC, and use `[received_from, received_before)`. Group days and profiles in `Europe/Amsterdam`, including 23/25-hour dates.
- Select sessions by their maximum reading time, not latest upload order. One analysis response uses a read-only REPEATABLE READ transaction; all overview statistics/charts share that read snapshot.
- Different responses may see newly uploaded/backfilled data. Return calculation time, requested range, actual first/last reading times, and count. Do not imply a cross-request frozen dataset.
- Aggregate from metric projections validated at ingest, without loading a month's complete Snapshots into Python/browser memory. Raw detail, CSV, and the latest complete reading retain canonical/hash/projection validation. Aggregate analysis is not a full integrity audit.
- Run synchronous database work off the event loop with short-lived connections/transactions.
- Retain Decimal/NUMERIC calculation and sufficient precision for accepted values. API measurements are decimal strings; absence is `null`, real zero is valid. Round for presentation, not before calculation. Convert to chart numbers only when finite/representable; otherwise preserve exact textual access and mark the plot value unavailable.

### C7. Energy, power, and daily statistics

**Cumulative energy.** Calculate import and export independently. A valid endpoint for one direction requires both tariff counters T1 and T2. Within the selected session/source, order by `(received_at, device_id, record_id)` and compare adjacent valid endpoints.

- If either tariff counter decreases, exclude that interval, record a reset/regression, and establish a new baseline at the later endpoint. Comparing only the combined total would hide a tariff regression and is not permitted.
- Skip endpoints with missing counters. Valid nondecreasing endpoints may bridge sampling gaps for period energy; preserve the gap warning and actual endpoint range.
- Use only endpoints inside the selected range. Fewer than two valid endpoints means unavailable, not zero. Never integrate sampled power, interpolate, or estimate missing energy.

**Daily energy.** Attribute an interval wholly within one Amsterdam date to that date. If the right endpoint is exactly the next local midnight, attribute it to the previous date. A genuinely cross-date interval contributes to a separate **cross-day unallocated energy** amount, without proportional splitting.

Return actual cumulative endpoint ranges, valid interval counts, and incompleteness reasons. Label daily values as energy over recorded intervals rather than asserting that partial data represents a whole day. For each direction:

**sum of date-attributed energy + cross-day unallocated energy = calculated period energy.**

**Power and peaks.** Return mean/minimum/maximum and valid count per time bucket, with at most approximately 2,000 buckets per series. Zoom requests finer data; short ten-second-scale ranges may show raw points. Empty buckets remain null, never zero; break lines at gaps and mark gaps inside otherwise populated buckets. Compute the sampled peak independently from raw projected values, returning its time and raw-record locator; ties use the earliest deterministic reading order. Export values are negative only in chart presentation; API values remain nonnegative.

Use the term **sampled peak**, not true instantaneous maximum. Grid import/export does not directly establish household consumption, total PV generation, or self-consumption.

### C8. Quality, average-day profiles, and phases

**Data quality.** Nominal expected count is the selected interval's actual duration in seconds divided by ten, rounded up. Display `actual / expected` capped at 100%, reporting excess records separately. This is nominal sampling coverage, not uptime.

- For adjacent readings more than 30 seconds apart, the gap starts ten seconds after the earlier reading and ends at the later one.
- Report leading/trailing uncovered intervals when the range edge is more than 30 seconds from the first/last reading; trailing missing time begins ten seconds after the last reading. With no readings, show the entire range as unobserved.
- Return valid/missing counts per metric and independent cumulative-endpoint validity for import/export.
- Summarize only persisted quality issues and allow raw-record lookup. List deliberate privacy redaction separately. Do not invent rejected-CRC totals, shutdown causes, session-completion status, or online status.
- Missing L2/L3 is “not provided,” not automatically a device fault.

**Average day.** Use 15-minute Amsterdam local-time slots. For each metric, average samples within each date/slot first, then equally average eligible dates. A date/slot is eligible for that metric only when valid count reaches 80% of the nominal count for its full actual duration. Return contributing-date counts; no eligible dates means null. Support all dates, Monday–Friday, and Saturday–Sunday. Merge the autumn repeated slot within its date, using its doubled actual duration for eligibility; do not fill nonexistent spring slots. Insufficient partial-date slots do not participate.

**Phases.** Provide aligned voltage, current, and power charts comparing L1/L2/L3, sharing a time axis/legend and keeping units separate. Power defaults to import with an export toggle. Reuse power bucketing/gap rules. Do not add undefined voltage-compliance decisions or fault alerts.

### C9. HTTP interfaces and compatibility

Keep `/api/admin/v1`, existing success/error envelopes, administrator cookies, CSRF, Host/Origin checks, and `no-store` behavior. Login retains existing form POST and redirect semantics. Bearer credentials do not authenticate management. Do not weaken existing body limits or fixed safe errors.

| Method and relative management path | Contract |
| --- | --- |
| `GET /workspace/sites` | Paginated site summaries, literal name/address substring search or exact UUID, reading count and latest-reading time |
| Existing site management endpoints | Add Server display names; existing requests remain valid |
| `PATCH /devices/{device_id}` | Edit display name only |
| `GET /sites/{site_id}/analysis/sessions` | Paginated session context, first/last reading, count, and default-selection information |
| `GET /sites/{site_id}/analysis/overview` | Statistics, energy, power curve, daily energy, and quality summary from one read snapshot |
| `GET /sites/{site_id}/analysis/power` | Power-chart zoom data |
| `GET /sites/{site_id}/analysis/typical-day` | Average-day slots and date grouping |
| `GET /sites/{site_id}/analysis/phases` | Phase series |
| `GET /sites/{site_id}/analysis/quality` | Quality statistics plus independently paginated gaps/problem-record locators |
| `GET /sites/{site_id}/analysis/latest` | Latest complete reading in the selected session, its device's authenticated-contact time, and the site's latest-reading time |

After context resolution, historical analysis requests explicitly supply `session_id`, `received_from`, and `received_before`. Shared response context includes the applied range, timezone, calculation time, count, and actual first/last reading times. Curves additionally report resolution; statistics include unavailability reasons. Latest observations are independent of the historical range and identify their session/device explicitly; device contact may concern activity outside the selected session.

- Missing sessions or sessions belonging to another site return 404. Invalid ranges and more than 31 dates return a fixed safe 422. Zoom bounds must remain inside the supplied global analysis range.
- New paginated results default to 50, maximum 100. Quality gaps and problem records have separate pagination controls. Use the existing detail endpoint for a complete Snapshot.
- Limit heavy historical analysis to two concurrent requests per process and set transaction-local statement timeout to ten seconds. Busy admission, timeout, or unavailable storage returns safe 503. Latest-reading polling remains lightweight and outside these heavy-analysis slots.
- Analysis slots are independent of the existing two CSV slots; errors, cancellation, and completion release owned resources. Preserve the existing bounded pool.
- Existing ingest, raw query, and CSV authentication, filtering, ordering, decimal representation, and complete-stream contracts remain unchanged.

Implemented query names (M5-08): `/workspace/sites` accepts `q` or `site_id` (mutually exclusive), plus `offset`/`limit`. Power/phase curves accept the paired `zoom_from`/`zoom_before` inside the required global range. Phases use `direction=import|export` (default import). Quality uses independent `gap_offset`/`gap_limit` and `problem_offset`/`problem_limit`. Typical day optionally accepts `group=all|weekday|weekend`; omission returns all three groups. Latest requires `session_id` and no historical range. The latest response keeps `snapshot`, `ingested_at`, `device_last_authenticated_contact_at`, and `site_latest_reading_received_at` separate.
