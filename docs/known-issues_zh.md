## LOGGER-001 — 独立试读可能使 Logger 卡在 `previewing`

- **状态：** 待修；2026-10-14 延期后，现已排入 [M4-01–M4-02](milestone/m4_zh.md#m4-01--串口-owner-与预览清理修复)，设计于 2026-10-15 就绪。主分支和已发布镜像均未包含修复。
- **受影响版本：** `v0.1.0-alpha.1`，Logger 镜像 `ghcr.io/t-liu93/watt-profile-logger:0.1.0-alpha.1`。
- **现场环境：** 所有者自行操作的树莓派，连接真实 USB/P1 设备。独立诊断工具已成功读到有效数据。开发代理未访问生产设备或数据。
- **影响：** 预览后本地配置可能不可用，创建现场、部署等修改按钮持续禁用。此问题与 M4 前尚未实现上传的预期行为无关。
- **计划修复分支：** 从 `main` 建立的 `fix/logger-preview-cleanup`。M4 在上传前实现并集成修复；本记录时该分支尚无修复实现。

### 复现与现象

1. 启动独立 Logger，在 **Site and settings** 保存容器内串口路径 `/dev/p1`。宿主机 `/dev/serial/by-id/...` 映射和设备数字组配置在部署环境文件中，不会自动填入应用保存的串口设置。
2. 尚未创建现场或部署时，进入 **Reading preview**，点击 **Read preview**。
3. 可能显示有效读数，随后出现 `serial_close_failed`。所有者遇到的故障中，请求结束后应用仍停在 `previewing`。
4. **Reload status** 仍显示 `Collection=previewing`，没有现场/会话，待上传数为零，无持久阻断，采集错误和运行时错误均为空。修改按钮持续禁用，没有取消预览操作；刷新网页不能清除该运行时状态。

预览应获取一条有效读数后释放临时串口 owner，不保存快照。网页每两秒轮询状态，不表示预览在持续采集。正常采集需要现场、部署以及 **Start / resume**。

### 证据与调查边界

检查 `src/watt_profile/logger/runtime.py` 发现两条相关路径：`_read()` 收尾和 `_release()` 都调用 `port.close()`，可能竞争关闭；`preview()` 在 `finish_preview()` 前执行 `_release()`，释放抛错时会跳过状态恢复。`logger/static/logger.js` 的 `controls()` 在运行时报告 `previewing` 时禁用修改按钮。部分释放失败不会写入 `runtime_error`，因此状态页可能没有错误提示。

仅使用假串口和临时 SQLite 的试验测试复现了重复关闭失败、关闭异常后残留预览状态。这些试验源码和测试改动已回滚，不属于已验收回归覆盖或已交付修复。尚未取得所有者树莓派上的具体驱动异常；硬件兼容与资源验收另行进行。

### 所有者临时恢复方式

在设备上包含 `compose.yml` 和 `.env` 的目录中，只重启 Logger：

```bash
docker compose --env-file .env -p watt-logger -f compose.yml restart logger
```

刷新网页并重新登录。此操作保留命名数据卷、已存配置、设备身份、Token 和已有记录，但重启期间会中断采集。受影响版本先避开独立 **Read preview**。创建/选择现场后点击 **Create paused deployment / switch site**，准备好后开始采集。所有者已确认恢复后成功创建现场／部署，随后在 M4 规划中报告 Pi 4 正持续采集，尚无 server origin，pending 不断增加。这是所有者报告的 M4 前运行，不是修复或上传器验证。恢复时不要删除数据卷。

### 后续修复验收条件

- 对每个串口句柄统一关闭责任或串行化关闭。保持独占，旧句柄或读取线程尚未释放时不得打开替代 owner。
- 成功、取消、超时、读取线程启动失败、串口收尾失败时，都恢复合适的生命周期并释放预览标记。已结束的请求不得使程序无解释地永久停在 `previewing`。
- 真实关闭/线程退出失败须在状态及 API 响应中明确显示，不泄露原始报文、凭据或私有异常文本。显示错误不等于可以安全复用未释放的句柄。
- 增加竞争收尾、真实关闭失败的确定性假串口回归测试；补充 API/浏览器覆盖，验证重复预览、状态响应、按钮恢复、创建现场/部署以及后续采集。预览不得创建持久快照或待上传记录。
- 使用独立合成资源执行适用的 runtime、生命周期、API、浏览器和容器持久性检查，只清理自己创建的资源；真实树莓派验证另与所有者安排。
- 在此记录验证及发布状态。不得移动或覆盖 `v0.1.0-alpha.1`；后续修复版本须另行授权并使用新版本号。
